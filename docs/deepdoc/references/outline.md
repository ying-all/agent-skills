# deepdoc 骨架：方法论型长文

## 三条硬规则（高于任何结构）

### 1. 例子先行

每章的第一个元素必须是一个**可复现的最小例子**，三件套缺一不可：

| 要素 | 写法 |
|---|---|
| 在哪做 | 页面 / 命令 / 环境，具体到能打开 |
| 输入什么 | 原样可复制的字符串 |
| 看到什么 | 具体现象：变粗、弹窗、报错原文 |

概念、分类、表格全部排在例子之后。**凑不出例子的章节，直接删。**

### 2. 篇幅服务于读完

默认 10–14 章、1–1.8 万字。超过 16 章必须在开篇说明理由。
宁可删章，不可为了整齐把每章压成同一长度。

### 3. 先定读者

动笔前写一句：「读者会 X，没做过 Y。」
不确定时按"有基础、没实操"写——**多给一步，少给一个名词**。

## 推荐结构（按需裁剪）

| # | 章节 | 必写 | 写什么 |
|---|---|---|---|
| 0 | 问题重述 | ✓ | 把模糊困惑翻译成 3 个真问题，亮出主线 |
| 1 | 本质 | ✓ | 一句话定义 + 成立条件 + 一个不成立的例子 |
| 2 | 心智模型 | ✓ | 流程图或决策树，读者以后每次套用 |
| 3 | 适用面 | | 分类表；指出最容易被忽略的一类 |
| 4–8 | 五步流程 | ✓ | 每步都按「例子 → 判据 → 反例」写 |
| 9 | 细节 / 构造 | | 边界条件、编码层、报错原文 |
| 10 | 绕过 / 对抗 | | 讲原理，不做字典 |
| 11 | 工具 | | 定位与误用，什么时候必须手工 |
| 12 | SOP | ✓ | 分阶段、可勾选、带时间预算 |
| 13 | 真实 vs 靶场 | | 差异表，具体到能力 |
| 14 | 防御 | ✓ | 措施 + 局限（为什么单靠一个不够） |
| 15 | 学习路径 | | 按难度排序，可执行 |
| 16 | 常见误区 | ✓ | 15–20 条，每条一句 |
| 17 | 速查卡 | ✓ | 三连式记忆块 |
| 18 | 边界 | ✓ | 适用场景与授权要求 |

结尾 **结语**：用 5 句话复述全篇的判断顺序。

## 每章模板

```markdown
## N. 标题（动词开头，≤ 20 字）

**先做这个**：打开 X，输入 `...`，你会看到 Y。
（三件套：环境、输入、现象。能截图就截图。）

> 一句话结论：这章主张什么，且可被反驳。

为什么成立：……
什么时候不成立：……

| 对照表 | 压缩信息 |
|---|---|

**常见坑**：一句。
```

## 深度检查（逐条过）

- 这章开头能照着做吗？做了会看到那个现象吗？
- 删掉这章，读者会损失什么？答不上来就删。
- 有没有"只有查过才知道"的细节？没有就补检索。
- 结论后面有没有"什么时候不成立"？
- 表格是不是在代替思考？（把段落硬拆成表格不算结构化）

## 反面模式

| 写法 | 为什么不行 |
|---|---|
| 抽象开篇："X 是……的越权" | 读者没有挂靠点，等于背名词 |
| "示意 payload" | 不能复现，读者照做看不到东西 |
| "首先…其次…最后…" 空转 | 结构在，信息密度为零 |
| 大段引用官方文档 | 读者自己会查，你要给的是判断 |
| 章节数量硬凑 | 18 章讲 6 章的内容，读起来像注水 |
| 结尾喊口号 | 结语要给判断顺序，不是打鸡血 |
